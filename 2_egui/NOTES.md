# Dev notes — config 2 (egui)

## Toolchain / dependency notes

- `eframe 0.36.2` + `egui_dock 0.21.1` + `egui-wgpu 0.36.2` (egui 0.36 line;
  wgpu 30). NOTE: eframe 0.36 changed `App::update(ctx)` → `App::ui(ui)` and
  `TopBottomPanel`/`CentralPanel` became the unified `egui::Panel` taking
  `&mut Ui` — docs/examples online mostly still show the old `update()` API.
- wgpu 30 renamed pipeline fields: `push_constant_ranges` → `immediate_size`,
  `multiview` → `multiview_mask`, vertex buffers are `Option<VertexBufferLayout>`.
- wasm needs `getrandom = { version = "0.2", features = ["js"] }` (rand dep).
- trunk 0.22.0 auto-downloads the matching `wasm-bindgen` (0.2.130) and
  `wasm-opt`; the `cargo install wasm-bindgen-cli` copy isn't strictly needed.
- `trunk serve` builds the **dev** profile by default; use
  `trunk build --release` for the artifact benchmark.

## "rust talib" choice

Used the pure-Rust `ta` crate (0.5) for EMA10/20/50 + SMA200 — the only
pure-Rust technical-analysis option that compiles to wasm (real `ta-lib` is a
C wrapper). VWAP and volume profile aren't in TA-Lib anyway, so they come from
`shared/indicators`.

**EMA seeding difference**: TA-Lib/`shared/indicators` seeds the EMA with the
SMA of the first `period` values (first `period-1` outputs NaN); `ta` seeds
with the first value and blends immediately. Tests NaN-pad our warmup for
parity and compare `ta` vs reference only after a 10x-period warmup with rel
tolerance 1e-9 (residual difference decays as `(1-k)^n`; at index ≥500 the
residual is < ~1e-7 absolute). SMA200 is the identical sliding-window sum;
compared with effectively zero tolerance from index 199.

## wgpu custom chart rendering

Implemented as a real `egui_wgpu::CallbackTrait` paint callback:

- CPU aggregates the 23,400-bar series to one candle per pixel column
  (O(width)) and emits position+color triangles in NDC relative to the
  callback's viewport rect: profile rects → wick/body quads → thick-quad line
  segments (6 indicator series, NaN gaps break segments).
- `prepare()` uploads the vertex list to a per-chart `wgpu::Buffer`
  (capacity grown on demand); `paint()` sets a scissor to the egui clip rect,
  binds a single pos2+color4 pipeline (premultiplied-alpha blend) and draws.
- Grid lines / price+time labels stay on `egui::Painter` (a few dozen shapes).
- If `cc.wgpu_render_state` is unavailable (e.g. glow backend) the app falls
  back to a pure `egui::Painter` path with identical aggregation (`paint_shapes`).
- wgpu MSAA: eframe's default `RendererOptions` has `msaa_samples: 0` → the
  render pass is single-sampled; the pipeline uses `MultisampleState::default()`.

## Streaming data model

- `Chart` holds the full generated day (`bars: Vec<Bar>`, 23,400) plus a
  `streamed` cursor; only `bars[..streamed]` is "arrived". `arrived()` is
  the working slice everywhere (render, indicators, live updates).
- Startup: `streamed = INITIAL_BARS` (4000), indicators computed over the
  preload only.
- `Streamer` (chart.rs): accumulates `rate * dt` per frame and delivers
  `ceil(rate*0.075)`-bar batches (~75 ms cadence, capped at 8 batches/frame
  after stalls) via `Chart::push_streamed` — O(1) EMA/SMA/VWAP per bar,
  volume profile recomputed once per batch over its 2000-bar window.
- Rate: `--rate=N` / `?rate=N`, per chart. Interactive default 1000/s
  (~19.4 s fill); bench default 2000/s (`--rate` still overrides) so
  catch-up stays ~10 s and the frame stats are meaningful.
- While catching up the view "follows" (extends to include newly arrived
  bars) so charts visibly fill out; a pan/zoom detaches the follow.
- After the stream is exhausted, interactive mode feeds 1 synthetic bar/s
  per chart (same LCG machinery as the bench live phases); `push_bar` has a
  `debug_assert` that the stream is done — live pushes mid-stream would
  misalign the cursor.
- `tests/indicators.rs::streamed_indicators_match_bulk` proves batched
  streaming produces identical series to one-shot bulk compute (EMA/SMA
  rolling-state FP drift covered by the same 1e-9 rel tolerance).

## Bench implementation

`--bench` (native) / `?bench=1` (web) drives phases from `App::ui`:
Warmup(20 frames, repaints forced) → **Stream (wait for all 8 catch-ups,
records `stream_catchup_ms` + `stream_rate_bars_per_sec` + frame stats in
`frame_time.stream_catchup`)** → indicator compute (20 runs × 8 charts,
median) → scripted pan/zoom 10 s (sinusoidal zoom 5%–95% span + center sweep,
all 8 charts) → live updates 1/s/chart 10 s → 100/s/chart 10 s → memory +
artifact sizes → emit JSON.

- Frame time = wall-clock interval between consecutive `ui()` calls while
  `request_repaint` is forced each frame (vsync-capped → ~74 fps on the test
  machine's 75 Hz display).
- Live bars are generated by a deterministic xorshift generator appending to
  each chart; indicator updates are O(1) incremental (rolling SMA sum, VWAP
  accumulators, EMA recurrence) except the volume profile which recomputes
  over its 2000-bar window each push.
- Memory: sysinfo RSS (native) / `performance.memory.usedJSHeapSize` (web,
  Chrome/Edge only).
- Native writes `../results/egui-desktop.json` directly. Web logs the JSON +
  `window.__bench_json` + attempts a download; `save_results.mjs` extracts it
  from a `--enable-logging=stderr` capture.

### Streaming numbers (v2)

- `--rate 4000` interactive: 155,200 bars (8×19,400) delivered in 4.89 s
  → ~31.7k bars/s total (request 32k — delivery keeps up).
- Bench at default 2000/s/chart: catch-up ~9.8 s at ~15.8k bars/s.
- Frame cost during catch-up is real but modest: desktop stream_catchup
  avg 21.4 ms/p99 135 ms (some large-batch frames + vertex-buffer growth),
  web avg 13.9 ms/p99 21 ms — the per-batch profile recompute and vertex
  rebuild dominate; sustained 15-30k bars/s across 8 charts is fine.
- `tests` grew `streamed_indicators_match_bulk` — batched replay equals
  one-shot bulk indicator output.

## Observed numbers (i9-9900K, RTX-class GPU, Edge headless)

- Desktop startup-to-first-chart showed ~13.6 s on first run — dominated by
  one-time wgpu driver/shader cache init; subsequent runs were much faster.
  Take the median of 3 runs per the schema rules.
- Frame time ~13.5 ms avg (vsync-locked at ~74.6 fps), identical across
  pan/zoom and live-update phases — the app is comfortably vsync-bound.
- Indicator compute ~1.0 ms/chart (~8.6 ms all eight), ~23k bars × 6 series.
- Memory ~170 MB idle / ~195 MB after bench (sysinfo RSS).
- Release exe ~15 MB; wasm (opt=z) ~7.7 MB; glue js ~0.15 MB.

## Gotchas

- `trunk serve` holds `dist/.trunk-lock`; run `trunk build` while serving is
  fine but a second trunk process waits on the lock.
- Headless Edge needs no `--disable-gpu` to get a real GPU adapter; with
  `--disable-gpu`/SwiftShader the app still runs (WebGL2 software rasterizer)
  but bench frame times are not meaningful.
- egui_dock 0.21 only has `DockArea::show_inside(ui, viewer)` (no
  `show(ctx)`); `scroll_bars` must be overridden to `[false, false]` or each
  tab gets useless scrollbars.
